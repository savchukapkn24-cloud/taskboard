## Лабораторна 4
Після git add файл переходить до індексу (Changes to be committed). git diff показує зміни робочих файлів відносно індексу; git diff --cached — підготовлені зміни.

git switch main перемикає гілку, а git merge приєднує історію іншої гілки до поточної. Конфлікт виник через різні зміни одного заголовка в main та ukr-title. Обидва варіанти поєднано, маркери видалено, виконано git add і commit.

## Лабораторна 2. Перша сторінка
Адреса при локальному запуску: http://127.0.0.1:5500/index.html. http — протокол, 127.0.0.1 — локальний хост, 5500 — порт, /index.html — шлях. Браузер є клієнтом, Live Server — сервером.

Для початкової сторінки потрібні два запити: HTML і логотип. Додатково браузер або розширення можуть запитувати favicon чи службові ресурси. У фінальній версії також завантажуються CSS і JavaScript.

Неправильний шлях images/logo1.png спричиняє 404: сервер не знаходить файл, а браузер показує alt. Редагування Elements змінює DOM у пам’яті, тому після F5 браузер знову читає файл і зміни зникають. document.title повертає назву вкладки; document.body.style.background = "lightyellow" тимчасово змінює фон.

Таблицю фактичних Network-запитів і скріншот 404 треба додати після запуску в DevTools. Нижче очікувані значення, а не вимірювання:

| Запит | Метод | Очікуваний статус | Тип | Фактичний розмір |
|---|---|---|---|---|
| index.html | GET | 200 | text/html | Переписати з Network |
| images/logo.png | GET | 200 | image/png | Переписати з Network |
| images/logo1.png | GET | 404 | Залежить від сервера | Переписати з Network |

## W-07. Семантична розмітка
Семантичні теги описують призначення блоків сторінки. header містить шапку, nav — навігацію, main — основний вміст. Це допомагає читати код і орієнтуватися користувачам допоміжних технологій.

Використані теги: header, nav, main, section, article, footer, figure, figcaption, h1, h2, p, strong, em, ul, li, a, img, table, thead, tbody, tr, th, td. Замість особистої фотографії використано умовний аватар. Перевірка W3C validator ще потрібна.

## W-10. Flexbox, адаптивність і форма
flex-wrap: wrap дозволяє елементам переходити на новий ряд, коли бракує ширини. Медіа-запит max-width: 600px розташовує профіль і поля форми вертикально. У .field.grow скидається flex-basis, щоб поле не ставало високим у колонці.

name задає назву поля під час надсилання даних, id ідентифікує елемент для JavaScript і label. required і maxlength обмежують введення. Перевірено обидві опубліковані сторінки у браузері з шириною вікна 390px: scrollWidth = 375px, горизонтальної прокрутки немає. Поля та профіль розташовані вертикально. Скріншот: ../images/mobile.jpg. Це перевірка розміру браузера, а не вручну вибраного пристрою в DevTools.

## W-12. JavaScript і DOM
Масив tasks зберігає стан. Обробники змінюють дані, викликають saveTasks(), а render() перебудовує список і лічильник. preventDefault() скасовує стандартне надсилання форми та перезавантаження сторінки.

createElement створює елементи, textContent записує введений текст без інтерпретації HTML. Один click-обробник на списку обслуговує нові задачі завдяки делегуванню подій. localStorage зберігає JSON під ключем taskboard.tasks, а try/catch обробляє недоступне сховище та некоректний JSON.

Таблиця для вправи налагодження (опис очікуваних проявів; у DevTools ще не відтворено):

| Зламав | Очікуваний прояв | Як виправити |
|---|---|---|
| #task-form → #task-from | TypeError при addEventListener, бо form дорівнює null | Виправити селектор |
| Прибрав preventDefault() | Форма перезавантажує сторінку | Повернути preventDefault() |
| Прибрав render() після push | Дані є в масиві, але список не оновився | Викликати render() |

### Виконані автоматичні перевірки
Перевірено синтаксис JavaScript командою node --check. У Node з моделлю DOM перевірено: відхилення назви з пробілів, додавання, очищення форми, буквальний текст <b>Тест</b>, виконання, видалення, повторне завантаження зі сховища та обробку пошкоджених даних. Усі ці перевірки пройшли; вони не замінюють огляд у справжньому браузері.

Усі локальні посилання й зображення існують. Спершу локальний сервер був недоступним вбудованому браузеру, тому після публікації перевірено сайт через GitHub Pages. Додавання задачі, її виконання, збереження виконаного стану після оновлення та видалення працюють у справжньому браузері. Навігація до сторінки автора й назад працює. Збережено реальні скріншоти images/screenshot.png та images/mobile.jpg. Таблиця Network, скріншот 404, W3C validator і ручні вправи з налагодження DevTools ще потребують виконання.
